What is couch?

couch is a shared watching space for a small group of creative friends — artists, musicians, filmmakers, people who love weird movies and good conversation. Think of it like a private theater on the internet: one person curates what's playing, everyone watches together, and there's a chat room to talk during the show.

Who is this for?

Small communities. Friend groups who want to watch things together without a corporation in the middle. People who make art and want to share it in a space that feels like theirs. Anyone who's ever thought "I wish there was a place online that felt like someone's living room."

It's not for big audiences, monetization, or growth hacking. It's for the opposite of that.

What can you do here?

  • Watch together — Films, shows, music videos, live streams. Whatever the curator puts on.
  • Chat while you watch — Built-in chat right next to the video. No separate app needed.
  • Visual effects — Anyone can add CRT scanlines, VHS distortion, glitch effects, color grading — overlaid on the video in real time, just by typing in chat.
  • No ads, no tracking, no algorithm — It's a room. You're in it together. That's the whole idea.

Why this matters

The internet used to be made of places like this — small, personal, hand-built. Somewhere along the way, we got convinced that only companies could run things. That you needed venture capital and a team of engineers. That's a lie they sold us.

Harmful people and greedy corporations already know how to use these tools. They use them to extract, to manipulate, to consolidate power. The story

couch was built by someone with very limited means — not much money, but a lot of love for sharing media with friends. Instead of paying for expensive streaming services, they used open-source software and AI assistance to build their own platform. The whole thing runs on a single rented server that costs less than a night out.

This project has been a side effort over about a year and a half, tinkered on in spare moments. It started with handwritten code — just figuring things out the old-fashioned way. Then Claude came along and helped accelerate the work. Later, as Cursor and Codex released newer versions, they joined the toolkit. Eventually, OpenClaw with DeepSeek took over the heavy lifting. Each tool arrived at a different stage and brought something new.

It wouldn't normally take a year and a half. That's just what a side project looks like — a few hours here, a weekend there, sometimes weeks of not touching it at all. But there's another reason: the tools kept getting dramatically better while this was being built. A year and a half ago, LLMs were impressive but limited. Today they're startlingly capable — and affordable enough that a single person with very little money can use them to build real infrastructure. If you started this project tomorrow, with today's tools, you could finish it in a fraction of the time. The speed at which this technology is improving is genuinely hard to keep up with.

Everything here — the streaming server, the playlist system, the visual effects engine, this website — is free and open-source. AI (specifically OpenClaw + DeepSeek) helped write the code, design the systems, and keep everything running. But you don't need AI to do this. Everything here can be built with freely available documentation, some patience, and a willingness to learn.

LLMs also make excellent tutors. The point isn't the technology. The point is showing people — especially people who've been told they can't — that they can. If one person with almost no resources can build a streaming platform for their friends, what could you build for yours?

How it works (simple version)

  1. A server (a computer in a data center, ~$10/month) hosts everything.
  2. Owncast handles the video streaming — like a self-hosted Twitch.
  3. A playlist system queues up videos and plays them in order.
  4. An effects system overlays real-time visual effects on the video.
  5. A web dashboard lets you manage everything without touching a command line.

Architecture

couch is a stack of four main components running on a single Linux server, fronted by Caddy as a reverse proxy with automatic TLS.

Component Breakdown

1. Owncast

The heart of the platform. Owncast is a self-hosted live streaming server with built-in chat, viewer count, and a clean web UI. It ingests video via RTMP and serves it to viewers via HLS.

  • Installed at /opt/owncast/owncast/
  • Updated via grab-latest.sh which pulls the latest GitHub release
  • Chat is built-in — no external chat service needed
  • Custom client-side code lives in data/public/couch-layers/

2. playlist-streamer

A Go application that manages playlists and streams video files (or YouTube URLs) to Owncast via RTMP. It supports multiple video providers, continuous looping, scheduled playback, and a web dashboard for management.

  • Providers: Local files, YouTube (via yt-dlp), Real-Debrid, HTTP streams, Kick/Twitch (stubs)
  • Modes: Continuous loop, scheduled (cron), interactive CLI, TUI studio, or HTTP API
  • Dashboard: Embedded web UI served from the same binary — playlist management, video upload, schedule calendar
  • File watcher: Auto-detects new files dropped in the videos directory (SFTP uploads)

Source: /opt/owncast/playlist-streamer/

3. layer-server

A lightweight Go server that manages real-time WebGL shader overlays on the Owncast video player. Viewers type commands in chat (like !preset crt), the server deduplicates and broadcasts the canonical state to all connected clients via SSE.

Available effects: CRT scanlines, chromatic aberration, color grading, digital glitch, VHS tracking/noise, pixelation, color inversion — with blend modes and per-layer opacity.

Source: /opt/owncast/layer-server/

  • Commands are text in chat (e.g. !fx crt scanlineIntensity 0.8)
  • State syncs instantly to all viewers via Server-Sent Events
  • Allowlist controls who can run commands
  • WebGL shader code runs client-side in the browser for zero server GPU cost

Setting Up Your Own

Prerequisites

  • A Linux server (any VPS works — $5-10/mo)
  • A domain name
  • Go 1.22+, ffmpeg, yt-dlp

Quick Start

  1. Install Owncast — Download the binary from owncast.online, run it, configure via /admin
  2. Clone the repo — git clone ... /opt/owncast
  3. Build playlist-streamer — cd playlist-streamer && go build -o playlist-streamer .
  4. Build layer-server — cd layer-server && go build -o layer-server .
  5. Set up Caddy — Point your domain at the server, configure reverse proxy for the components
  6. Install systemd units — So everything starts on boot and restarts on failure
  7. Drop videos in /opt/owncast/playlist-streamer/videos/ — They auto-appear in the playlist

Stream Key Security

Never commit config.local.yaml to version control. It contains the Owncast stream key and API tokens. Use restricted file permissions (0600) and .gitignore.

Useful Commands

# Restart everything
systemctl restart owncast playlist-streamer layer-server

# View logs
journalctl -u playlist-streamer -f

# Check layer state
curl -s https://couch.dsp.coffee/layers-api/state | python3 -m json.tool

# Force a layer preset (bypasses allowlist)
curl -s -X POST http://localhost:9100/layers-api/state \
  -H 'Content-Type: application/json' \
  -d '{"cmd":"preset","args":["crt"]}'

# Update Owncast to latest release
cd /opt/owncast && bash grab-latest.sh
